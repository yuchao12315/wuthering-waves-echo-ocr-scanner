# 鸣潮活动技能等级与共鸣链数据调研

- 调研日期：2026-07-28
- 调研范围：库街区官方 Wiki 页面/API、库街区官方公告与活动说明、当前项目内已有数据和运行时代码
- 写入约束：本报告仅记录结论与模型建议，不修改业务 JSON

## 结论摘要

1. 库街区官方角色详情 API 当前只公开 `Lv 1` 至 `Lv 10` 的技能倍率表。对项目已有的 59 个角色详情 ID 逐一重新请求后，59/59 个响应的技能表最高列均为 `Lv 10`，未发现 `Lv 11-20` 列或隐藏的高等级倍率字段。
2. 同一 API 的“共鸣链”组件均为 7 个 HTML 表格行，即 1 行表头和 6 条共鸣链效果。59/59 个角色均如此，未发现第 7 链或更高链数据。
3. 官方 1.4 版本内容说明能够证明“失序梦途/深坠异想奇境”具有活动内独立强化：公告使用了“联梦融觉”“角色升阶”等表述。但公告没有写明角色技能实际提升至 Lv20，也没有写明共鸣链突破六链。
4. 截至本次访问，**未能从一手来源验证**“心之集域或其他官方活动中，角色的实际技能等级可以达到 Lv20”。同样，**未能从一手来源验证**活动中的实际共鸣链可以高于常规六链。不能用攻略、社区 Wiki、截图转述或本地未知来源数组补足这一结论。
5. 项目本地确实已经保存大量第 11-20 档倍率，但缺少来源、版本、角色详情 ID、采集时间和活动适用范围等元数据。它们可以作为待核验候选数据，不能标记为“库街区官方 Lv11-20 数据”。
6. 在可映射的 Lv10 数据中，`characters-base` 与 2026-07-28 采集的官方详情数据没有实质数值冲突；有 3 处约 0.01-0.02 的展示舍入差，以及 2 处官方拆行、项目合并表达的等价差异。仍有部分技能名称无法唯一映射，不能据此断言其相同或不同。

## 一手来源与证据

### 1. 库街区角色详情 API

官方接口：

- `POST https://api.kurobbs.com/wiki/core/catalogue/item/getEntryDetail`
- 请求体：`id=<角色详情页 item id>`
- 角色详情页示例：[秧秧·玄翎官方详情页](https://wiki.kurobbs.com/mc/item/1519669180526559232)
- API 地址：[库街区官方角色详情 API](https://api.kurobbs.com/wiki/core/catalogue/item/getEntryDetail)
- 访问日期：2026-07-28

API 响应中的角色信息位于：

```text
data.content.modules[*].components[*]
```

技能和共鸣链分别通过组件标题定位：

```text
title == "技能介绍"
title == "共鸣链"
```

本次使用项目现有 [kuro-character-skill-details.json](/Users/yuchao/ww/outputs/kuro-character-skill-details.json) 中的 59 个官方详情 ID 重新请求接口，并直接扫描原始组件 HTML：

| 检查项 | 结果 |
| --- | --- |
| 成功响应 | 59/59 |
| 技能表最高等级列 | 59/59 均为 `Lv 10` |
| 出现 `Lv 11-20` | 0/59 |
| 共鸣链表格行数 | 59/59 均为 7 行 |
| 高于六链的额外行 | 0/59 |

技能表实际列为 `Lv 1`、`Lv 2`……`Lv 10`。延奏技能、谐度破坏等没有等级倍率表的技能，不构成高等级数据缺失证据。

“共鸣链”组件没有单独的 `sequence` 字段；当前公开结构是 HTML 表格。每个角色均为表头“名称/效果”加六条效果。因此可以结构化提取标准 1-6 链，但不能从该接口生成第 7 链以上数据。

### 2. 官方活动说明

一手来源：

- [「暗夜叩响白昼之门」1.4版本内容说明](https://www.kurobbs.com/mc/post/1306312565924175872)
- [库街区官方活动/公告列表 API](https://api.kurobbs.com/forum/companyEvent/findEventList)
- 访问日期：2026-07-28

官方内容说明确认：

- “失序梦途”包含“深梦历程”“异梦封锁”“永夜重现”。
- “永夜重现”允许自由选择共鸣者，并受到“联梦融觉”能力加持。
- “深坠异想奇境”存在“角色升阶”，官方还曾调整活动中部分角色在该界面下的技能描述。

这些内容只能证明活动有独立的临时强化与角色专属机制。该公告未给出以下信息：

- 没有“技能等级提升至 20”或同义的明确规则；
- 没有 Lv11-20 倍率表；
- 没有“共鸣链高于 6”或第 7 链以上效果；
- 没有说明“角色升阶”等价于常规技能等级增加；
- 没有说明活动倍率提升通过常规技能等级表计算。

因此，本报告不能把“联梦融觉”“角色升阶”“角色强化”解释为实际技能 Lv20，也不能把活动专属效果解释成更高共鸣链。

## 概念边界

| 概念 | 本次可验证含义 | 是否有 Lv20/高链一手证据 |
| --- | --- | --- |
| 常规养成技能等级 | 官方详情倍率表公开到 Lv10 | 仅验证到 Lv10 |
| 常规共鸣链 | 官方详情组件包含 6 条效果 | 仅验证到六链 |
| 活动内临时强化 | “联梦融觉”“角色升阶”等活动专属机制 | 已验证存在，但数值层级未公开 |
| 实际技能等级 | UI/规则明确把技能等级设置为某个等级，并按对应等级倍率取值 | 未验证 Lv20 |
| 倍率增益 | 对原技能倍率做加成、替换或追加伤害 | 不能自动视为技能升级 |
| 共鸣链效果 | 标准 1-6 链效果或活动临时授予的类似效果 | 未验证高于六链 |

## 项目现有高等级数据

[characters-base.json](/Users/yuchao/ww/src/data/characters-base.json) 中技能倍率数组长度分布：

| 倍率项数 | 技能数 | 角色范围 |
| ---: | ---: | --- |
| 20 | 1003 | 大多数技能 |
| 19 | 66 | 今汐 21、折枝 14、长离 17、鉴心 13、秧秧 1 |
| 10 | 2 | 桃祈 2 |

这些数组没有随条目保存以下来源元数据：

- 官方 URL 或 API item ID；
- 原始表格/客户端资源路径；
- 游戏版本；
- 采集日期；
- 等级编号与数组下标映射；
- 常规或活动适用范围；
- 校验哈希或原始响应快照。

因此不能仅凭数组长度认定第 20 项是官方活动“技能 Lv20”。尤其是，官方详情 API 本身没有提供这些列。

当前 Web 与小程序运行时还会把技能等级索引限制为 0-18：

```ts
const levelIdx = Math.max(0, Math.min(18, skillLevel - 1))
```

对应 [Web 伤害计算](/Users/yuchao/ww/src/lib/damage.ts#L238) 和 [小程序伤害计算](/Users/yuchao/ww/miniprogram/lib/damage.ts#L238)。这意味着即使某技能有 20 项倍率，运行时最高也只读取第 19 项；第 20 项当前不可达。共鸣链则明确限制为 6：

```ts
const activeChainLevel = Math.min(6, chainLevel)
```

在没有确认第 20 项来源和等级语义前，不建议直接把运行时上限改为 20。

## 能否结构化填充更多数据

### 可以立即可靠填充的范围

- 从官方详情 API 填充标准技能 `Lv1-Lv10` 倍率；
- 从“共鸣链”组件填充标准 1-6 链名称和效果；
- 保存技能文本、治疗量、分支强化及数据来源元数据；
- 把项目现有第 11-20 项保留为“来源待核验”数据，不冒充官方 API 数据。

### 当前不能可靠填充的范围

- 不能从官方详情 API填充 Lv11-20，因为接口没有这些列；
- 不能从官方详情 API填充第 7 链以上，因为组件只有六链；
- 不能从现有官方活动说明推导 Lv20 倍率；
- 不能把活动内倍率增益或角色强化换算成实际技能等级；
- 不能把活动临时获得的类似链效果写成标准第 7 链以上数据。

若后续能取得可复核的官方客户端公开资源，至少需要同时验证资源归属、版本、字段含义、等级编号、活动作用域和倍率选择逻辑，才可将其作为新的一级来源。当前环境未发现可供核验的官方客户端资源包，因此本次没有据此补数。

## 数据模型建议

不要继续只用无来源的字符串数组表达所有场景。建议后续引入显式等级和来源，但本次不修改业务 JSON：

```ts
interface SkillLevelValue {
  level: number
  value: string
  scope: 'standard' | 'event'
  sourceId: string
}

interface DataSource {
  id: string
  authority: 'kuro-wiki-api' | 'kuro-official-notice' | 'official-client'
  url: string
  itemId?: string
  gameVersion?: string
  accessedAt: string
  evidencePath?: string
  verification: 'verified' | 'unverified'
}

interface EventSkillOverride {
  eventId: string
  mode: 'set-level' | 'multiplier-bonus' | 'replace-multiplier' | 'extra-effect'
  skillLevel?: number
  value?: string | number
  temporary: true
  sourceId: string
}

interface ResonanceChainState {
  standardLevel: 0 | 1 | 2 | 3 | 4 | 5 | 6
  eventEffects?: EventSkillOverride[]
}
```

关键原则：

- 数组下标不再隐式代表等级，显式保存 `level`；
- 常规数据与活动临时强化分层保存；
- “设置技能等级”“倍率增益”“替换倍率”“追加效果”分开建模；
- 标准共鸣链固定表达 0-6，活动效果单独记录，不伪造第 7 链；
- 每条高于 Lv10 的数据必须有可点击的一手来源、访问日期和版本；
- 来源未验证的数据可以保留，但必须标记 `unverified`，不能进入默认伤害计算。

## 最终判断

当前最稳妥的项目策略是：

1. 以库街区官方详情 API 的 Lv1-10 和六链为标准数据基线；
2. 保留项目已有 20/19 项数组，但先补来源审计，不把第 11-20 项标为官方；
3. 继续把活动强化建模为独立 override；
4. 在找到明确的一手来源证明“实际技能 Lv20”及其倍率表之前，不开放 Lv20 计算；
5. 在找到明确的一手来源证明“高于六链”之前，不扩展标准共鸣链上限。

结论性表述：**未能从一手来源验证心之集域或其他官方活动会把角色实际技能等级提升至 Lv20，也未能验证共鸣链高于六链；库街区官方详情 API 当前只提供 Lv1-10 和标准六链数据。**
